### Rulings (made before dispatch)

- **R1 (T2 `make_probe_n`)** — Routing `pls64` to `regressors.make_regressor("pls")` returns a bare `PLSRegression(n_components=64)`, which raises whenever the readout has fewer than 64 features or rows. That is not merely a test problem: the real run's `raw|moments` readout has 10 features at 1-comp and 30 at 3-comp, so `pls64` would crash on those readouts in production. Ruling: `make_probe_n` special-cases ONLY `"ridgecv"`; `pls64` falls through to `geo.make_probe`, whose `pls{k}` branch wraps it in `_PLSWrapper` and clamps `k = min(k, n_samples-1, n_features)`. Keep `LARGE_N_EXTRAS = ("ridgecv", "pls64")` for panel composition. Cost if wrong: none — clamping is strictly more permissive and is what the few-shot family already does.
- **R2 (T2–T5 expected test counts)** — T2 defines 8 test functions, not 7. Corrected expected totals: T1 → 61, T2 → **69**, T3 → **76**, T4 → **78**, T5 → **82**, T7 → 82. Cost if wrong: an implementer chases a phantom failure.
- **R3 (T4 `_write_tiny_bank`)** — `n=900` with `make_split`'s default `n_eval_a=500, n_eval_b=500` leaves an EMPTY pool, so `draw_indices` would raise. Ruling: build the synthetic bank with `n=1200` (500 + 500 + 200 pool ≥ the largest monkeypatched rung of 50). Do NOT relax `make_split` or add a small-n branch to production code — adjust the fixture, exactly as step 6 required. Cost if wrong: none; the fixture is synthetic.
- **R4 (T2 `test_every_panel_is_nonempty_and_buildable`)** — Constructing `tabpfn_pca50` inside a unit test may trigger a model-weights download, making the suite network-dependent and slow. Ruling: skip probe names starting with `tabpfn` in that test's construction loop while still asserting panel composition (`tabpfn_pca50` present at n≤50, absent above). TabPFN construction is exercised by the real run and by step 6's confirm panel. Cost if wrong: TabPFN construction is not unit-covered; its panel membership still is.
