### Rulings (made before dispatch)

- **R1 (T7 `run_screen`)** — Wave 2 regenerates the `pooling="mean"` readouts wave 1 already scored (4 stages × 4 norms × 3 comps = 48 cells), re-running `score_readout` + `readout_diagnostics` for an identical result. Ruling: skip any wave-2 readout whose result key is already in `results["readouts"]`. Why: pure waste, ~30-45 min of the screen budget, no behaviour change. Cost if wrong: none — the skipped cells are byte-identical recomputations.
- **R2 (T6 `score_readout`)** — The plan constructs the probe *inside* the draw loop. `graph_prop` builds a 4,716-node kNN graph over up-to-9,216-dim data at construction, so 100 draws = 100 graph builds = hours per cell, and its own docstring promises the graph is built once. Ruling: construct each probe once per `(probe, n_train)` and re-fit it per draw. Safe because every estimator here fully resets state in `.fit()`. Cost if wrong: a probe with construction-time state that `fit` does not reset would leak information across draws — mitigated by the existing per-draw `try/except` and by `graph_prop`'s `fit` overwriting `_f` wholesale.
- **R3 (T5 `make_probe`)** — `tabpfn_pca50` as specified delegates to `make_fewshot_regressor(..., pca_basis=None)`, i.e. an inductive `PCA(n_components=50)` fitted on 20 rows, which sklearn rejects (`n_components > n_samples`). Every TabPFN draw at n_train=20 would fail. Ruling: `make_probe("tabpfn_pca50")` fits the PCA-50 basis on `X_all` (transductive, the study's declared and legitimate unlabeled lever, and what step 5 did) and requires `X_all` like `graph_prop`. Cost if wrong: TabPFN's reduction is transductive while some panel-mates' is inductive — must be, and is, stated in the report's scope.
- **R4 (T6 `readout_diagnostics`)** — Two full randomized SVDs per readout plus a full-dimensional 5-fold RidgeCV on up to 9,216 dims, over ~456 readouts, estimates at 9–15 h — past the plan's own 8 h screen budget. Ruling: (a) fit ONE `PCA(k_full≤200, whiten=True)` and take participation ratio / effective rank from its `explained_variance_` (whitening does not change eigenvalues); (b) compute `ridgecv_full_r2` on those top-`k_full` PCs rather than on full dimensions, with the docstring stating exactly that and noting it equals the full-dim value whenever d ≤ 200. Key name unchanged so T8's `DIAG_KEYS` and T6's test still hold. Cost if wrong: for d > 200 the "ceiling" diagnostic truncates to a 200-dim subspace and could understate a readout whose label signal sits below PC 200 — acceptable for a *ranking* diagnostic, and the reportable numbers never come from it.
- **R5 (T3 `load_bank_cache`)** — `np.load(..., mmap_mode="r")` is not meaningful for a `.npz` (numpy either ignores it or raises). Ruling: drop `mmap_mode="r"`; `NpzFile` is already lazy per array. Cost if wrong: none.
- **R6 (T9 Step 5)** — The estimate formula `per * (60+72+288) * 3` double-counts and misstates the grid. Correct count per comp: 12 raw + 60 wave-1 = 72, plus 80 *new* wave-2 readouts after R1 = 152; × 3 comp counts = **456**. Ruling: use `per * 152 * 3 / 3600`. Cost if wrong: only the printed ETA is off.
- **R7 (T9/T10)** — The plan calls `step6_REPORT.md` a gitignored output, but `.gitignore` ignores only `code/eval_outputs/**/_cache/` and `**/*.npz`; steps 1–5 shipped their reports inside `code/eval_outputs/` as tracked files. Ruling: commit step 6's `.md` reports and `.png` figures alongside the tracked docs; only `bank.npz` and `_cache/` stay ignored. Cost if wrong: a few hundred KB of figures in git, matching existing precedent.
