SpectralFM — internal reference

Training architecture, plainly

SpectralFM trains a data2vec-audio backbone to represent 1D radio-telescope signals — 245-sample spectra treated as if they were audio — self-supervised, with no labels. This page is a map of what actually trains today: the model, the loss, the data, and how checkpoints move between training and evaluation. For exact commands, see CLAUDE.md in the repo.

00

Two things get trained here

A convolutional front-end turns each 245-point signal into a short sequence of feature vectors; a 12-layer transformer encodes them. Two separate training processes build on that:

1

Backbone (regular) training

hydra_train + spectralfm_base.yaml, launched by sweep_dataset.sh

Self-supervised: the encoder learns to predict its own masked-out regions, using a slowly-updated copy of itself (an EMA "teacher") as the target — the data2vec recipe, applied to spectra instead of waveforms.

no labels
2

Autoencoder / reconstruction training

code/train_reconstruction.py, or the same hydra_train entry point with recon_loss/ configs

Bolts one or more decoder heads onto a backbone (frozen or trainable) and teaches them to rebuild the original 245-point signal, to test how much information survives at each depth.

on top of a backbone

Both use the same underlying model class — fairseq's data2vec_audio — just configured differently. An older, HuggingFace-based training path predates both and is scheduled for removal (see TASKS.md) — it isn't covered here.

01

Model architecture

Feature extractor

A 5-layer 1D conv stack, explicitly sized for 245-frame input (245 → 243 → 241 → 239 → 237 → 47 tokens), 512 channels, layer_norm mode: 

conv_feature_layers = [(512, 3, 1), (512, 3, 1), (512, 3, 1), (512, 3, 1), (512, 5, 5)]

This has to be set explicitly everywhere the model is built — the class default is the stock wav2vec2/speech stack (~320× downsampling), which collapses a 245-frame input to a degenerate ~0-length sequence.

✓ fixed this session

spectralfm_base.yaml — the config sweep_dataset.sh launches by default — never set conv_feature_layers, so it was silently falling back to that broken default. Added the explicit 5-layer value, matching spectralfm_full_train.yaml and train_reconstruction.py's own conv-stack constant, which both already had it right.

Backbone transformer

12-layer transformer encoder, 768-dim, EMA teacher for self-distillation. post_extract_proj lifts the 512-d conv output to 768-d — a bare linear layer by default, or a small MLP when a config asks for it (post_extract_proj_type: mlp_gelu).

⚠ read before writing a new config

train_only_fe defaults to true — it freezes every parameter except the feature extractor. This supports FE-only reconstruction experiments, but it means any new full training config must set model.train_only_fe: false explicitly, or training silently becomes FE-only. spectralfm_base.yaml was missing this until this session too — also now fixed.

Reconstruction decoder heads (autoencoder training only)

Up to three heads, each rebuilding the 245-point signal from a different depth, all sharing the same 5-layer ConvTranspose1d "mirror" architecture that reverses the feature extractor (47 → 245):

HeadReads fromWired up by
FE decoderconv FE output--recon_path fe or lambda_recon_fe > 0
Proj decoderpost-projection featureslambda_recon_proj > 0 (Hydra only)
Transformer decoderfull transformer output--recon_path transformer or lambda_recon_trans > 0

Per-component init and freeze flags let any of FE / LayerNorm / proj / transformer / each decoder head be independently warm-started from a different checkpoint and independently frozen — this is how "reconstruction heads on top of a frozen, already-trained SSL backbone" gets built.

02

Loss setup

Backbone — self-distillation (SSL)

Standard data2vec loss, computed inside the model itself. The masked student's output is regressed against the EMA teacher's average of its top 8 transformer layers (target-normalized). With loss_beta: 0 this reduces to plain MSE.

Reconstruction — weighted MSE + total variation

Each decoder head has its own independently-weighted MSE against the original signal (any can be zeroed to disable that head's loss without removing the head): 

TV(x) = mean(|x[i+1] − x[i]|)
loss  = λ_fe·(MSE(head_fe) + λ_tv_fe·TV(head_fe))
      + λ_trans·MSE(head_trans) + λ_proj·MSE(head_proj)

Best setting found so far: λ_tv_fe = 0.1 — a mild smoothness regularizer; higher values over-smooth the reconstruction.

finding, not yet reflected in defaults

Reconstruction quality and downstream representation quality are decoupled — the original SSL-pretrained backbone remains the only one that's label-informative (R²=0.44); every reconstruction-trained variant tried so far scores ≈0. Prefer decoders on top of a frozen SSL backbone over training through it, until this changes.

03

Data sources

.tsv manifests over .wav directories, built by fairseq/create_manifests.py. Manifest generation is a one-time, per-subset step — not something you redo before every training run. See CLAUDE.md's Manifest generation and Datasets sections for the exact command and which subsets exist.

04

Checkpoint loading

Three different mechanisms exist because they solve different problems — using the wrong one is the most common way to get a silently wrong, non-crashing result.

1

Warm-starting a component while building a new model

code/recon_components.py, used by both train_reconstruction.py's --init_*_ckpt flags and Hydra's model.init_*_ckpt fields.

Each loader auto-detects which of several known checkpoint layouts the source .pt uses — plain fairseq audio, data2vec_multi, or the older standalone apr28_fe_recon save — and remaps keys accordingly. Lazy-imported from build_model(): if code/ isn't on PYTHONPATH when launching via Hydra, these fields silently no-op with a warning — you get random init where you expected a warm-start.

2

Loading a full checkpoint for eval / inference

code/model_loader.py:load_fairseq_checkpoint, used by code/evaluation_runner.py and other code/eval_*.py scripts — the older, fairseq-dependent eval tooling.

Inspects the checkpoint's embedded config for any /storage/noy/... path and remaps it to /mnt5/noy/... when running on Geoffrey, auto-setting skip_pretrained_weights if no local copy of a referenced base checkpoint exists. Backfills config keys missing from older checkpoints, including train_only_fe=False, so old checkpoints evaluate as full models rather than silently as FE-only.

3

The zero-fairseq eval package

code/eval/checkpoint_loader.py — a separate, from-scratch loader, unrelated to the two above.

Detects checkpoint format purely from its state-dict keys and rebuilds an equivalent HuggingFace model shell with the matching feature extractor swapped in, entirely without a fairseq install. See code/eval/EVAL_OVERVIEW.md.

06

Train → eval bridge

Once you have a checkpoint from either training path, evaluate it with code/eval/runner.py — see the quick-run command in CLAUDE.md. It works from any of the checkpoint formats above without needing to know which training path produced it.
