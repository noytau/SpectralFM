03

Architecture

One model class, data2vec_audio, configured two different ways depending on which of the two training paths is in use.

Signal path

245 samples
  → 5-layer 1D conv FE  (512ch, layer_norm, no bias)      245→243→241→239→237→47 tokens
  → post_extract_proj    512d → 768d  (linear, or MLP+GELU+LN when swept)
  → 12-layer transformer encoder_embed_dim=768, EMA teacher for self-distillation

The 5-layer conv sizing is explicit everywhere the model is built — the class default is wav2vec2's stock ~320× downsampling stack, which collapses a 245-frame input to nothing. Any new config must set it, not inherit the default.

Block diagram — signal path & loss wiring

What backprops into what, independent of any one training step's freeze config. The three reconstruction decoders (§ above) tap the FE, projection and transformer outputs respectively; the d2v self-distillation loss reads the EMA teacher's clean forward pass.

forward pass d2v backprop reconstruction backprop shared reconstruction target

Backprop into FE / projection / transformer only happens when that block is unfrozen for a given training step — which components train vs. freeze on each step of the active pipeline is in §06.

Two training paths, one model class

PathTrainsEntry point
Backbone (SSL)The data2vec_audio backbone itself, self-supervised, no labelsfairseq_cli.hydra_train + spectralfm_base.yaml
Reconstruction ("3AE")Decoder head(s) that rebuild the 245-pt signal from a frozen or trainable backbonecode/train_reconstruction.py, or the same Hydra entry point with recon_loss/*.yaml

Reconstruction decoder heads

Up to three, each tapping a different depth, all sharing the same mirrored ConvTranspose1d architecture (47→245):

HeadReads fromEnabled by
FE decoderConv FE output (post-LayerNorm)--recon_path fe / lambda_recon_fe>0
Proj decoderPost-post_extract_proj featureslambda_recon_proj>0 — standalone trainer only, see §06
Transformer decoderFull transformer output--recon_path transformer / lambda_recon_trans>0

Per-component --init_*_ckpt and --freeze_* flags let FE / projection / transformer / each head be independently warm-started and independently frozen — this is the mechanism behind every "decoder on top of a frozen SSL backbone" experiment in §06.

Config gotcha

train_only_fe defaults to true — it freezes everything except the feature extractor. spectralfm_base.yaml explicitly sets it false for full backbone training. Any new from-scratch config that skips this silently trains FE-only.

Loss

Backbone: standard data2vec self-distillation — masked-student output regressed against an EMA teacher's top-8-layer average, target-normalized, plain L2 (loss_beta: 0).

loss = λ_fe·(MSE(head_fe) + λ_tv·TV(head_fe)) + λ_trans·MSE(head_trans) + λ_proj·MSE(head_proj)
TV(x) = mean(|x[:,1:] - x[:,:-1]|)          // best λ_tv found so far: 0.1
04

Evaluations

code/eval/ — zero fairseq dependency, four checkpoint modes (hf / file / dir / multiple), seven methods, one HTML+markdown report per run.

MethodQuestion it answersCore metric
embedding_similarityDo embeddings group same-stack samples better than raw input?match_score (0–100, >50 = embedding wins)
signal_reconstructionCan each pipeline stage decode back to the original signal?per-pathway MSE (fe / proj / tr)
noise_robustnessHow stable are embeddings under 6 injected-noise types?clean-vs-noisy cosine similarity
clusteringDoes KMeans on embeddings recover true stack structure?ARI / NMI / silhouette
label_regressionDo embeddings encode parameter_0 better than raw input?RidgeCV R² (emb vs input), 1/2/3-component configs
structured_similarityHow does similarity structure evolve across pipeline stages?2×2 cosine-similarity heatmap panel
checkpoint_comparisonWraps the five above across N checkpointsone comparison table + full figure set

Quick run

python -m eval.runner \
  --data_source /mnt5/noy/SpectralFM/fairseq/data/nova_data/single_channel_10k/wav \
  --checkpoint_mode multiple --checkpoint_paths ckptA.pt ckptB.pt \
  --evals checkpoint_comparison signal_reconstruction \
  --recon_ckpt /path/to/3ae_ckpt.pt \
  --nova_data_dir .../nova_data --labeled_data_dir .../nova_data/labeled_data \
  --output_dir /mnt5/noy/SpectralFM/code/eval_outputs

~10 min/checkpoint on one RTX 2080 Ti (label regression on 2,000 samples is the slow stage). Checkpoint format (fairseq / 3ae / fe_recon / tr_recon / state_dict) is auto-detected from state-dict keys — you don't need to know what produced a given .pt before pointing the runner at it.

05

Training

Backbone training is fairseq-native and launched like any Hydra job; reconstruction training has a simpler standalone entry point plus an equivalent Hydra path for sweeps.

Backbone (regular) training

Launched via sweep_dataset.sh (one RunAI job per subset in its SUBSETS=(...) array), or a single custom runai submit pointing task.data= at any manifest. Checkpoints save every 5,000 updates (last 3 kept). common.wandb_run_name is dead config — the actual W&B run name comes from the WANDB_NAME env var, else it falls back to the checkpoint save-dir's basename.

Reconstruction / autoencoder training

Worked example — freeze a pretrained backbone, train only the two decoder heads on top of it:

python code/train_reconstruction.py --mode train --recon_path transformer \
  --ckpt base_libri_official.pt \
  --init_fe_ckpt base_libri_official.pt --init_transformer_ckpt base_libri_official.pt \
  --freeze_fe_v2 --freeze_transformer \
  --lambda_recon_fe 1.0 --lambda_recon_trans 1.0 --lambda_tv_fe 0.1 \
  --lr_head_fe 1e-4 --lr_head_trans 1e-4 \
  --data_dir .../single_channel_1k/wav --n_samples 950 --steps 10000
Key constraint

min_sample_size must be 1 — the base LibriSpeech config default (32000) silently drops every 245-frame SpectralFM wav.

06

Experiments done so far & plan

The headline finding shapes everything currently in flight — read that first, then the pipeline it motivated.

Headline finding — T6, 2026-08-04

Reconstruction quality and representation quality are decoupled. The original SSL-only backbone is the only one that's label-informative (R² = 0.441 on the label-regression probe, beating raw input's 0.377). Every reconstruction-trained variant tried so far — TV-swept FE decoder, MLP projection, recon heads on the base_libri transformer — scores R² ≈ 0, regardless of decoder architecture or loss weight. The transformer a decoder sits on dominates every second-order choice.

Working conclusion: build reconstruction capability on top of an SSL-informative backbone rather than training through a reconstruction-oriented one. That's the direction the T8–T12 pipeline below tests directly.

Results — training-improvement round (Aug 3–4, 2026)

Three questions, one training session on Geoffrey: does total-variation regularization help the FE decoder (T4)? Does an MLP projection preserve more signal than the bare linear one (T2)? What changes when reconstruction decoders sit on the SSL-trained backbone instead of the speech-pretrained one (T5 / T5b)? T6 then ran the full embedding-level suite across all resulting checkpoints.

Active pipeline — 3AE + d2v joint round (T8–T12)

Five strictly sequential steps, each fixing the previous step's winning checkpoint and unfreezing one more component. Full joint fine-tune runs last, once every earlier link is validated on its own.

Step 0
T8 — FE pretrain, d2v-only done

FE trains from random init against the pure d2v loss; projection + transformer frozen at base_libri (or projection joint-trained — the winning variant). No decoder yet.

Step 1
T9 — attach FE decoder next up

FE + projection train jointly from random init; FE decoder attached for the first time. Loss = λ_d2v·d2v + λ_fe·recon_fe. Config work only — precedented by the existing basemerge Hydra config.

Step 2
T10 — projection fine-tune, 3 capacities new engineering

FE frozen at T9's checkpoint; projection trains (linear / mlp768 / mlp2048). Requires porting a proj_recon_decoder + lambda_recon_proj into the native model — confirmed absent from data2vec_audio.py by direct inspection, not yet built.

Step 3
T11 — transformer fine-tune planned

FE + projection frozen at T9/T10's winners; transformer trains from base_libri on NOVA data with the transformer decoder attached. The most direct test of the headline finding — compared against T5b.

Step 4
T12 — full joint fine-tune planned

All three components + all three decoders train together, seeded from T9–T11's winners. Blocked on T10 landing first. Hardest run to attribute if metrics move, since three components change at once.
