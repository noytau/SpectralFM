Transformer reconstruction — tensor sizes, projections, LayerNorms, and freezing the FE

RunAI / hardware: transformer signal-recon (--recon_path transformer, default batch) targets NVIDIA A5000 or A6000-class GPUs. Use NODE_POOLS that only route to those SKUs. Optional RUNAI_NODE_TYPE=A5000 or A6000 passes --node-type to pin a label; leave it unset in fairseq/submit_signal_recon_100k_grid_runai.sh if jobs stay Pending because few nodes expose run.ai/type=A6000.

Reference: code/train_reconstruction.py (--recon_path transformer), and Fairseq fairseq/examples/data2vec/models/data2vec_audio.py forward(..., features_only=True, mask=False). Batch size B is arbitrary; time axes depend on input waveform length after striding.

Typical tensor shapes (inside Data2VecAudioModel → head)

C = transformer embedding dim (768 in the bundled SpectralFM-style config). T = number of time frames after the conv FE (depends on input length; the standalone FE+245-bin debug path in this repo uses T = 47 when the conv stack downsamples to that length).

StageTensor shapeNotes
Input waveform [B, L] L = samples per clip (Nova manifest WAVs; not limited to 245).
Conv FE output [B, 512, T] feature_extractor (5-layer SpectralFM conv stack in Hydra-equivalent cfg).
After transpose + extractor LayerNorm [B, T, 512] Fairseq LayerNorm on the 512-d conv channel dim (model.layer_norm in code) — not the same module as the head’s LN below.
post_extract_proj (internal projection) [B, T, 512] → [B, T, C] Linear or MLP (build_post_extract_proj): maps conv feature dim 512 → C (768) so the stack can enter TransformerEncoder.
Transformer encoder out (features_only) [B, T, C] Returned as out["x"]; this is what the reconstruction head consumes.
Head stem (Conv1d 1×1) [B, C, T] → [B, 512, T] Transpose [B,T,C] to channels-first; project C → 512 so the same MirrorDecoder as the FE path (512-wide) can run.
Head pre_decoder_ln [B, T, 512] torch.nn.LayerNorm(512) over the feature dim — mirrors the FE standalone path’s nn.LayerNorm(512) after the CNN.
MirrorDecoder [B, 512, T] → [B, 1, 245] ConvTranspose stack (same as --recon_path fe).
Training target [B, 245] First 245 samples of the input waveform; MSE against recon.squeeze(1).

Two different “projection” layers (do not confuse them)

  • post_extract_proj (inside Data2VecAudioModel): part of the official audio encoder; maps conv 512-d tokens to transformer C-d tokens before self-attention.
  • Head stem (TransformerMirrorDecoder): maps transformer C-d sequence back to 512 channels so the shared MirrorDecoder (designed for the FE’s 512-wide grid) can upsample to 245 bins.

Two different LayerNorms

  • model.layer_norm (Fairseq, on 512): applied right after the conv FE in data2vec_audio.py (on the [B,T,512] stream).
  • pre_decoder_ln in the reconstruction head: LayerNorm(512) on the stem output, matching the FE reconstruction script’s layer_norm(fe_out.transpose(...)) pattern before MirrorDecoder.

What happens to the FE when training the transformer path?

  • Default (no --freeze_fe): the entire Data2VecAudioModel is trained, including feature_extractor, layer_norm, post_extract_proj, TransformerEncoder, and the external head — same end-to-end idea as --recon_path fe, but with the full data2vec audio encoder instead of the standalone CNN.
  • With --freeze_fe: the conv FE (feature_extractor) and the Fairseq extractor layer_norm (512-d) have requires_grad=False. The script also sets feature_grad_mult = 0 so the conv runs inside torch.no_grad (as in the upstream model when FE is frozen): no optimizer updates and no autograd storage through the conv. Still trained: post_extract_proj, TransformerEncoder, dropout modules, and the stem + LN + MirrorDecoder head — gradients flow through post_extract_proj into the frozen conv outputs as usual for “frozen feature extractor” setups.

Optional --fe_ckpt (pretrained FE weights)

After building/merging the backbone from the main --ckpt, you can pass --fe_ckpt /path/to.pt to re-merge only feature_extractor.* and layer_norm.* from a second Fairseq checkpoint (same key/shape rules as the main loader). Typical pattern: --ckpt none for a fresh transformer, plus --fe_ckpt (e.g. Libri base or a RunAI long-train .pt) to inject conv + extractor LN weights, then --freeze_fe to keep that FE fixed while the transformer and head train.

Example commands

# Full Data2VecAudio + head, init from one Fairseq checkpoint
python3 code/train_reconstruction.py --mode train --recon_path transformer \
  --ckpt fairseq/base_libri_official.pt --manifest ... --out_dir ...

# Libri FE (frozen) + train transformer + head; random init for non-FE weights from --ckpt none
python3 code/train_reconstruction.py --mode train --recon_path transformer --ckpt none \
  --fe_ckpt fairseq/base_libri_official.pt --freeze_fe --manifest ... --out_dir ...

Full-model training is GPU- and memory-intensive; --freeze_fe reduces conv-side work and optimizer state, but the transformer + head are still large.
