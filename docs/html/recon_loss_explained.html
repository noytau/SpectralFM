3b. _mean_pool (line ~1367)

def _mean_pool(self, x, padding_mask):
    """Mean-pool over time; padding_mask True = padded (ignored)."""
    if padding_mask is None:
        return x.mean(dim=1)   # [B, T, D] → [B, D]
    # ...masked mean for variable-length sequences
Fixed-length spectrograms: All spectrograms in this project are exactly 245 samples. After the FE, the sequence is always 49 time steps. padding_mask is None in practice, so _mean_pool simply averages all 49 frames into a single 512-d vector. The masked path is defensive code for potential future use with variable-length inputs.

3c. _recon_target (line ~1377)

def _recon_target(self, source):
    d = self.cfg.recon_output_dim  # 245
    x = source.float()
    return x[:, :d]  # first 245 values of raw input

4. recon_only Mode

When model.recon_only=true, the entire transformer/EMA/masking pipeline is bypassed:

What happens in __init__

if getattr(cfg, "recon_only", False):
    self.final_proj = None          # prevents EMA creation
    for name, p in self.named_parameters():
        if "feature_extractor" not in name and "fe_recon_decoder" not in name:
            p.requires_grad = False
    # → Only FE + fe_recon_decoder are trainable (~4M params)

What happens in forward()

# After FE + layer_norm:
if getattr(self.cfg, "recon_only", False):
    result = {"losses": {}}
    recon_target = self._recon_target(source)
    fe_p = self._mean_pool(fe_seq, padding_mask)
    pred_fe = self.fe_recon_decoder(fe_p)
    loss_fn = F.mse_loss if cfg.recon_loss_type == "l2" else F.l1_loss
    result["losses"]["recon_fe"] = loss_fn(pred_fe, recon_target) * lambda_recon_fe
    return result   # ← early return, no transformer

Why recon_only exists: train_only_fe still runs the full transformer and EMA teacher on every forward pass — wasting ~70% of compute on frozen components. recon_only skips all of that, making training ~3× faster for the same number of updates.

6. Mean-Pool Bottleneck

The current reconstruction pipeline has a fundamental information bottleneck:

FE output: [B, 49, 512] (49 time steps × 512 channels) │ mean over time │ ▼ Pooled: [B, 512] (temporal order lost) │ MLP decoder │ ▼ Output: [B, 245] (must reconstruct 245 ordered values)

Mean-pooling collapses 49 time steps into a single vector, discarding all temporal ordering. The decoder receives a 512-dim "bag of features" and must reconstruct 245 ordered spectrogram bins — a fundamentally lossy mapping.

Potential fixes explored in experiments:

  • Conv1D decoder: Skip mean-pool; use [B, 512, 49] → ConvTranspose1d → [B, 1, 245]
  • Interpolate decoder: Interpolate [B, 49, 512] → [B, 245, 512] then project per-step
  • Flatten decoder: [B, 49×512] → MLP → [B, 245] (large but preserves position)

7. Interpolation Decoder (InterpReconDecoder) — Deep Dive

The interpolation decoder bypasses mean-pooling entirely. It preserves temporal structure by upsampling the FE sequence from 47 time steps back to 245, then reduces each position's 512 channels to a single scalar.

Step-by-step forward pass

Step 1: Input from FE fe_seq = [B, 47, 512] (47 time steps, 512 channels each) Step 2: Transpose to channels-first (required by F.interpolate) x.transpose(1,2) → [B, 512, 47] Step 3: Linear interpolation — stretch 47 → 245 F.interpolate(x, size=245, mode="linear") → [B, 512, 245] Each of the 512 channels is independently resampled from 47 to 245 points. This is like stretching a signal — intermediate values are linearly blended from their nearest neighbors. Step 4: Transpose back to time-first x.transpose(1,2) → [B, 245, 512] Step 5: Per-position MLP (shared weights across all 245 positions) fc: Linear(512→128) → GELU → Linear(128→1) At each of the 245 positions, the 512-dim vector is compressed to 1 scalar. fc(x).squeeze(-1) → [B, 245]

Architecture diagram

fe_seq [B, 47, 512] │ │ transpose → [B, 512, 47] │ │ F.interpolate(mode="linear", size=245) │ ┌─────────────────────────────────────────┐ │ │ ch₀: ──●──●──●──...──●── (47 pts) │ │ │ ↓ ↓ ↓ ↓ │ │ │ ch₀: ─●─●─●─●─●─...─●─●─ (245 pts) │ │ │ (× 512 channels, independently) │ │ └─────────────────────────────────────────┘ │ │ transpose → [B, 245, 512] │ │ per-position MLP (shared weights): │ ┌───────────────────────────────┐ │ │ pos₁: [512] → [128] → [1] │ │ │ pos₂: [512] → [128] → [1] │ │ │ ... │ │ │ pos₂₄₅: [512] → [128] → [1] │ │ └───────────────────────────────┘ │ ▼ pred_fe [B, 245]

Code (data2vec_audio.py, line ~585)

class InterpReconDecoder(nn.Module):
    def __init__(self, in_dim: int, out_dim: int):
        super().__init__()
        self.out_dim = out_dim          # 245
        self.fc = nn.Sequential(
            nn.Linear(in_dim, 128),     # 512 → 128
            nn.GELU(),
            nn.Linear(128, 1),          # 128 → 1
        )

    @property
    def needs_full_sequence(self) -> bool:
        return True                     # no mean-pool needed

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        x = x.transpose(1, 2)          # [B, 47, 512] → [B, 512, 47]
        x = F.interpolate(x, size=self.out_dim, mode="linear",
                          align_corners=False)   # [B, 512, 245]
        x = x.transpose(1, 2)          # [B, 245, 512]
        return self.fc(x).squeeze(-1)   # [B, 245]

Why interpolation works well

  • Preserves temporal ordering — unlike mean-pool, each output position corresponds to a specific region of the input.
  • Lightweight — only ~66K trainable parameters (vs ~4M for the MLP decoder).
  • Smooth upsampling — linear interpolation produces smooth transitions between the 47 FE frames, which matches the smooth nature of spectrograms.
